# Telegram Trigger Bot (Render + Upstash Redis)

Бот для автоматических ответов в групповых чатах с меню управления в Telegram и веб-панелью в стиле дашборда (чёрный фон, стеклянные панели, шрифты Unbounded / JetBrains Mono, локальные SVG-иконки).

## Профили игроков (новое)

Бот умеет показывать карточку игрока NoomiNora в стиле веб-панели: чёрный фон, Unbounded, белые пилюли мест в топах. В ответ уходит **только картинка, без текста**.

| Команда | Что делает |
| --- | --- |
| `Аккаунт` (или `/аккаунт`, `/account`) | Свой профиль: берёт аккаунт по привязанному Telegram (`/bot/account?tg_id=`), аватарку — из Telegram |
| `Чекнуть 90000` (или `/чекнуть 90000`, `/check 90000`) | Чужой профиль по ID в игре |
| `Чекнуть` ответом на сообщение | Ищет игровой профиль по Telegram-аккаунту автора сообщения |
| `Чекнуть` без ID и без ответа | Подсказка по команде |

На карточке: аватарка из Telegram, ник, ID, дата регистрации, премиум, часы, перехваты, лучшая сессия и место в каждом из трёх топов (белые пилюли `#1 ИЗ 2274`, топ-3 помечены точкой).

- Работает в ЛС и в группах, для всех пользователей бота; регистрируется **до** catch-all обработчиков, так что перебивает автоответы. FSM-меню админа не затрагивается (`StateFilter(None)`).
- Анти-спам: не чаще одной карточки в 4 секунды на пользователя.
- Данные: `GET /players/{account_id}` (публичная карточка: часы/перехваты/longest + все три ранга), `GET /bot/account?tg_id=` с заголовком `X-Bot-Secret`. Сервер API: переменная `GAMESERVER_API` (по умолчанию `https://87.58.220.8:8443`), секрет — `GAME_API_SECRET` (есть встроенное значение по умолчанию; лучше задавать через переменные окружения).
- Аватар чужого профиля: бот не может узнать Telegram чужого ID напрямую, поэтому связки `account_id → tg_id` кэшируются в Redis (`bot:tglink:{account_id}`, 30 дней) каждый раз, когда кто-то использует «Аккаунт». Пока связки нет — рисуется стеклянный круг с первой буквой ника.
- Если игрок закрыл профиль (403 «Профиль закрыт владельцем») — красивая карточка «Профиль закрыт»; 404 — «Игрок не найден»; недоступен API — «Сервер игры не отвечает».
- Рендер: `profile_card.py` (Pillow), шрифт `fonts/Unbounded.ttf` лежит рядом, `requirements.txt` дополнен `Pillow>=10.0.0`. Если Pillow/шрифт недоступны — бот продолжает работать, только отвечает текстом.

## Управление премиумом

Telegram-пользователи с ID `7831019966` и `6793480366` могут отправить `Выдать прем 19` или `Забрать прем 19`. Число — игровой ID. Команды управляют бессрочным премиумом через `POST /admin/toggle_prem`.

Задайте `GAME_ADMIN_TOKEN` в окружении бота. Это Bearer-токен администратора игры. Для штатного игрового сервера бот проверяет отпечаток сертификата. При замене самоподписанного сертификата задайте его новый SHA-256 в `GAME_ADMIN_TLS_SHA256`.

## Что нового в этой версии
- **Реакции на медиа**: на стикер, фото, видео, голосовое (ГС), гифку, видео-кружок или аудио бот отвечает с заданной вероятностью (по умолчанию **50%**). Для каждого типа медиа — свой шанс срабатывания и свой список вариантов, из которых бот выбирает случайный.
- **Ответы на посты канала (ТГК)**: когда в группе появляется пост от имени канала, бот отвечает **первым**. Отдельные тумблеры для групп и для самого канала, шанс срабатывания и варианты ответов с кнопками.
- **Поведение и защита**:
  - «Игнорировать других ботов» — защита от бесконечных петель бот-бот (вкл. по умолчанию);
  - кулдаун автоответов в секундах — бот не будет отвечать чаще, чем раз в N секунд в одном чате;
  - случайная задержка перед медиа-реакцией — реакции выглядят живыми.
- **Счётчики статистики**: ответы по триггерам, медиа-реакции и ответы на посты канала видны в панели, есть кнопка сброса.
- Новая вкладка панели **«Автоответы»**: карточки для каждого типа медиа, редактор вариантов (текст, медиа, кнопки), слайдеры шанса.
- Данные в Redis не удаляются и не перезаписываются: все новые настройки хранятся в **отдельных ключах** (`bot:media_replies`, `bot:channel_reply`, `bot:settings`, `bot:stats`), старые триггеры в `bot:triggers` не трогаются.

## Приоритет ответов
1. Если текст/подпись сообщения подходит под триггер — бот отвечает заготовкой (старое поведение сохранено).
2. Если триггер не сработал и это медиа — проверяется реакция для этого типа медиа (шанс → случайный вариант).
3. Посты канала: сначала проверяются триггеры, если ничего не совпало — автоответ на пост канала.

## Что внутри архива
- `bot.py` — полный код бота и веб-панели.
- `requirements.txt` — список зависимостей (`aiogram`, `aiohttp`, `redis`).
- `README.md` — эта инструкция.

## Ключи Redis
| Ключ | Что хранит |
| --- | --- |
| `bot:triggers` | Заготовки-триггеры (без изменений) |
| `bot:media_replies` | Настройки и варианты реакций на каждый тип медиа |
| `bot:channel_reply` | Настройки и варианты ответов на посты канала |
| `bot:settings` | Поведение: игнор ботов, кулдаун, задержка |
| `bot:stats` | Счётчики ответов |
| `bot:last_reply:{chat_id}` | Время последнего автоответа (кулдаун) |

Перед крупными изменениями лучше сохранить копию: в панели есть кнопка **«Скачать JSON-бэкап»** (или `GET /api/export` с заголовком `X-Admin-Password`). Бэкап включает только триггеры.

## Пошаговый запуск на Render

### 1. Подготовьте GitHub-репозиторий
1. Создайте новый приватный репозиторий на GitHub (например, `my-tg-trigger-bot`).
2. Загрузите в него файлы `bot.py` и `requirements.txt` из этого архива.

### 2. Создайте веб-сервис на Render
1. Войдите на [render.com](https://render.com/) через GitHub.
2. Нажмите **New +** → **Web Service**.
3. Выберите ваш репозиторий и нажмите **Connect**.
4. Заполните настройки сервиса:
   - **Name:** любое имя (например, `tg-trigger-bot`)
   - **Region:** `Frankfurt (EU Central)`
   - **Runtime:** `Python 3`
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python bot.py`
   - **Instance Type:** выберите бесплатный тариф **Free** (`$0/month`).

### 3. Добавьте переменные окружения (Environment Variables)
На той же странице (или во вкладке **Environment** после создания) добавьте 4 переменные:
- `BOT_TOKEN` — ваш новый токен от `@BotFather`
- `ADMIN_ID` — ваш Telegram ID (`7831019966`)
- `REDIS_URL` — строка подключения из Upstash Redis (начинается с `rediss://default:...`)
- `WEB_PASSWORD` — пароль для входа в веб-панель

Нажмите **Deploy Web Service**. Через 1–2 минуты в логах появится сообщение `Веб-панель запущена на порту...`, а бот начнёт отвечать в Telegram.

### 4. Чтобы бот не засыпал (UptimeRobot)
Бесплатный Render усыпляет контейнер, если на сайт не заходят 15 минут. Чтобы бот работал 24/7:
1. Скопируйте адрес вашего сайта на Render (вида `https://tg-trigger-bot.onrender.com`).
2. Зарегистрируйтесь на бесплатном сервисе [uptimerobot.com](https://uptimerobot.com/).
3. Нажмите **Add New Monitor**:
   - **Monitor Type:** `HTTP(s)`
   - **URL:** `https://ваш-домен.onrender.com/ping`
   - **Monitoring Interval:** `5 minutes`
4. Сохраните монитор. Теперь UptimeRobot будет пинговать адрес `/ping` каждые 5 минут, и бот не уснёт.

## Идеи следующих обновлений
- Белый/чёрный список чатов: реагировать только в выбранных группах.
- Несколько вариантов ответа для обычных триггеров (рандом между ними) — сейчас это есть у медиа-реакций и постов канала.
- Импорт JSON-бэкапа обратно в базу прямо из панели.
- Emoji-реакции на сообщения (Telegram reactions) с настраиваемым шансом.
- Приветствие новых участников группы.
- Тихие часы: не отвечать ночью.
- Журнал последних сработавших автоответов в панели.
- Команда `/stats` в Telegram-меню для быстрого просмотра статистики.
